# 남은 작업 (백로그)

마지막 갱신: 2026-10-12, v0.10.1 기준

- 스펙(`docs/superpowers/specs/2026-10-07-gameboy-emulator-design.md`) §9의 마일스톤 0–8은 모두 끝났다.
- 이 문서는 그 뒤에 남은 일을 모은다.
  1. 사람이 직접 확인할 것
  2. 리뷰에서 미뤄 둔 사소한 문제(Minor)
  3. 스펙에서 일부러 뺀 기능
- 항목을 처리하면 지우거나 `~~취소선~~`과 처리한 버전·PR 번호를 남긴다.

## 1. 직접 확인할 것

자동 테스트로는 확인할 수 없어서 실제로 앱을 써 보며 확인해야 한다.

### 1.1 스펙 §1.6 성공 기준

- [ ] **(기준 1)** 포켓몬 크리스탈을 처음부터 진행할 수 있다. 앱을 다시 켜도 배터리 세이브와 게임 속 시계(RTC)가 유지된다.
- [ ] **(기준 2)** 소리 끊김 없이 60fps(59.73fps)를 유지한다.

### 1.2 v0.10.1 (사용성 개선, PR #22)

- [ ] 설정에서 버튼 키를 지정할 때 F1–F10을 누르면 지정되지 않고 계속 입력을 기다린다.
- [ ] Esc로 일시정지한 채 다른 ROM을 열면 바로 실행된다.
- [ ] 일시정지 중에는 CPU 사용량이 줄어든다.
- [ ] VRAM 창 배경 맵 탭에 "배경 / 윈도우" 버튼이 보인다.
- [ ] 종료 중에 스테이트 단축키를 누르면 상태 표시줄에 이유가 뜬다. 재현하기 어려우니 건너뛰어도 된다.

### 1.3 v0.10.0 (디버거 VRAM·I/O·채널 음소거, PR #20)

- [ ] 툴바 "디버거" 메뉴에서 VRAM 창과 I/O 창을 열 수 있다.
- [ ] VRAM 창의 타일·배경 맵·스프라이트(OAM)·팔레트 탭이 게임 화면과 맞게 보인다. CGB 게임(골드/크리스탈)에서는 VRAM 뱅크 1과 CGB 팔레트도 보인다.
- [ ] I/O 창에서 소리 채널을 끄면 실제로 그 채널 소리만 빠진다.
- [ ] 채널을 끈 채로 ROM을 바꿔도 음소거가 유지된다.

### 1.4 v0.9.0 (디버거 CPU·메모리, PR #18)

- [ ] 툴바 "디버거"를 누르면 CPU 창과 메모리 창이 뜨고, 게임 화면은 그대로 보인다.
- [ ] CPU 창에서 "일시정지" 뒤 "명령 1개"를 누르면 PC와 디스어셈블리가 한 줄씩 나아간다. "프레임 1개"를 누르면 화면이 한 프레임 나아간다.
- [ ] 디스어셈블리 줄 왼쪽 ○로 브레이크포인트를 걸면 그 주소에서 멈추고 상태 표시줄에 알린다. "계속"을 누르면 이어서 진행한다.
- [ ] 메모리 창에서 주소(예: `C000`)를 입력해 이동할 수 있다. 입력하는 동안 게임이 키보드에 반응하지 않는다.

## 2. 미뤄 둔 사소한 문제 (Minor)

- 각 마일스톤 최종 리뷰에서 Minor로 판정해 미룬 항목이다. 이미 고친 것은 뺐다.
- 앞쪽 마일스톤(M0–M7) 항목 중에는 그 뒤 작업으로 사정이 바뀐 것이 있을 수 있다. 손대기 전에 코드에서 다시 확인한다.

### 2.1 사용성

- 입력칸에서 Tab으로 포커스가 버튼으로 옮겨진 뒤 Tab을 누르고 있으면 배속이 걸린다(해는 없음).
- Tab으로 툴바 버튼에 포커스가 간 상태에서 Enter(게임의 Start)를 누르면 그 버튼이 눌릴 수 있다.
- 일시정지 중 "프레임 1개"가 브레이크포인트에 걸리면 상태 표시줄 알림은 다음 갱신에 뜬다. 디버거 라벨은 바로 바뀐다.
- 기존 `.sav`를 읽지 못한 세션에서 게임이 RAM에 쓰고 나면 스테이트 불러오기가 계속 거부된다. 그때 안내 문구가 오해를 준다.
- 스테이트를 저장할 때 썸네일을 먼저 쓴다. 그래서 스테이트 쓰기가 실패하면 썸네일과 스테이트가 어긋날 수 있다.
- 헤더 제목이 빈 ROM은 창 제목이 "Aragorn vX - "로, 상태 표시줄이 " 실행 중"으로 보인다.
- ROM을 읽지 못했을 때 오류 문구에 OS 언어의 `io::Error` 문장이 섞인다.
- 파일 열기 대화상자(rfd)에 부모 창이 없다. Windows에서는 메인 창이 "응답 없음"으로 보일 수 있다.
- VRAM 창이 열려 있으면 갱신마다 텍스처를 최대 41개 다시 올린다. 일시정지 중에는 생략할 수 있다.

### 2.2 세이브·RTC

- 저장하거나 불러올 때마다 1초 미만의 RTC 시간이 버려진다. 다른 에뮬레이터도 같다.
- 일시정지하거나 배속 중에 앱을 끄면, 마지막 저장 뒤의 에뮬레이션 시간 대신 실제 흐른 시간이 RTC에 적용된다(M6b 결정 3의 결과).
- 세션이 세이브가 있는지 확인할 때 `battery_ram(0)`으로 RAM 전체를 복사한다. `has_battery_save()` 같은 쿼리로 바꿀 수 있다.
- 저장 실패 재시도 주기가 에뮬레이션 프레임 기준이다. 그래서 무제한 배속에서는 재시도가 잦아진다.
- RAM을 켜 둔 채 1초보다 짧은 간격으로 계속 쓰는 게임은 저장이 한없이 미뤄질 수 있다. 최대 저장 지연이 없다.
- `step_instruction`("명령 1개")은 배터리 변경 확인(`track_battery`)을 부르지 않는다. 변경 표시는 카트리지에 남아 있어서 저장이 늦어질 뿐이다.
- `.sav.bak` 쓰기가 실패하면 본 세이브 저장도 막힌다.
- DMG 팔레트(`Ppu.palette`)가 스테이트에 저장된다. 팔레트 설정 기능을 넣으면 스테이트에서 빼고(`skip`) 호스트 값을 유지해야 한다.

### 2.3 소리

- 믹서의 sum·capacitor 값이 유한하지만 아주 크면 한 번 딸깍 소리가 난다.
- 192kHz를 넘는 출력 장치에서는 피치가 틀어진다(믹서 상한).
- 기본 샘플 형식이 U8/I8/I24/F64인 장치에서는 소리가 나지 않는다.
- 시작할 때 출력 장치가 없으면, 나중에 연결해도 다시 시도하지 않는다.
- 출력 장치를 다시 여는 작업이 UI 스레드에서 돈다. Pulse 초기화 때문에 최대 2초 멈출 수 있다.
- 고정 버퍼가 거절되어 기본 버퍼(Pulse 2초 콜백)로 열면 큐가 작다. 오래된 샘플을 버려서 일부 완화했다.
- 오디오 콜백이 처음 불릴 때 버퍼를 할당한다.
- CGB 속도 전환 때 DIV를 리셋하기 전에 속도를 바꾼다. 그래서 512Hz 단계가 한 번 더 또는 덜 돌 수 있다(들리지 않음).

### 2.4 에뮬레이션 정확도

- LCDC 비트 0이 0일 때 배경 색 0을 흰색으로 고정하지 않고 BGP를 거친다.
- LCD를 켜면 0번 줄을 모드 2로 시작한다. 실제 하드웨어는 모드 0이라, STAT 비트 5 인터럽트가 한 번 더 걸릴 수 있다.
- LYC STAT 조건이 LCD 켜짐 여부를 보지 않는다. LCD가 꺼진 동안 STAT에 쓰면 인터럽트가 걸릴 수 있다. 실제 하드웨어 동작은 확실하지 않다.
- MBC5 진동 카트리지(0x1C–0x1E)의 진동 비트 3을 RAM 뱅크 비트로 취급한다.
- 크기가 16KB의 배수가 아닌 ROM은 마지막 부분 뱅크를 읽을 수 없다.
- SVBK의 부트 직후 값이 0xF9다. 문서상으로는 0xF8일 수 있다. 게임이 쓰기 전에 읽으면 1로 보인다.
- 공개 함수 `Ppu::read_oam`·`write_oam`은 0xFE00–0xFE9F 밖의 주소를 받으면 패닉한다. 버스는 그런 주소를 넘기지 않는다.
- 조작된 스테이트를 불러오면 디버그 빌드에서 오버플로가 날 수 있다(`bus.dots≈u64::MAX`, RTC 레지스터 0xFF, `sub_second`). 릴리스 빌드는 값을 감싸서 넘긴다.

### 2.5 디버거

- 인터럽트 디스패치만 한 step도 그 PC를 실행한 것처럼 실행 흔적에 남는다.
- OAM DMA 중에는 `Bus::peek`가 OAM을 0xFF로 돌려준다. 그래서 디버거에서 전송 중 OAM 내용이 가려진다.

### 2.6 업데이트·배포

- 소프트 업데이트가 있다고 뜬 상태에서 자동 다운로드를 켜도, 다음 확인 때까지 다운로드가 시작되지 않는다.
- 소프트 다운로드가 멈추면 계속 다운로드 중 상태로 남는다. 감시(watchdog)가 없어서 그 실행 동안 다시 확인하지 않는다.
- 소프트 업데이트의 "적용 후 재시작"은 재시작 전 세이브 저장(flush)이 실패해도 진행한다. 오류는 보여 주고 기록한다.
- 서명 검증에 `verify_strict`가 아니라 `verify`를 쓴다. 정책 만료 시각이 없어서, 예전에 서명된 정책을 다시 보내는 공격(replay)을 막지 못한다.
- `policy.latest`가 프리릴리스면 강제 업데이트 확인을 건너뛴다. 태그 패턴 `v*.*.*`가 프리릴리스 태그도 받아들인다.
- 릴리스 워크플로를 다시 돌리기 어렵다. 같은 릴리스가 이미 있으면 `gh release create`가 실패한다.
- 바이너리에 ureq가 두 메이저 버전으로 들어 있다. 우리 쪽은 2, velopack 쪽은 3이다.
- 설정 파일에서 필드 하나만 형식이 틀려도 설정 전체가 초기화된다.
- 손으로 고친 설정 파일에서 기본 키로 대체될 때, 그 키가 다른 기능과 겹칠 수 있다.

### 2.7 테스트·개발 환경

- **테스트 공백:**
  - 2배속 RTC 속도. 코드는 dot 기준이라 정확하다.
  - ROM을 바꾼 뒤 음소거 재적용(`app.rs`)
  - 음소거 중 PCM12/34 값 불변
  - DMG OBP0/OBP1 선택이 `sprite_image` 색 콜백까지 이어지는지. PPU 단은 테스트했다.
  - 강제 업데이트 중 에뮬레이션 정지
  - IME=0으로 HALT에서 깨어나 여러 바이트 명령을 실행하는 경우
  - DIV/TAC 쓰기로 일어나는 TIMA 오버플로
  - FF46을 연속 사이클에 두 번 쓰는 경우
  - HDMA 도착지 0x1FF0 감싸기
  - 뱅크 1 스프라이트 타일
  - 2배속 HBlank DMA
  - DMG에서 KEY1/HDMA5 값 불변
- **세이브 스테이트 고정 파일:**
  - CGB·ROM 전용 카트리지만 다룬다. MBC/RTC/DMG 배치는 검증하지 않았다.
  - `ARAGORN_WRITE_STATE_FIXTURE`를 설정하면 고정 파일을 덮어쓴다. 주석에는 "파일이 없을 때만"이라고 되어 있다.
- **CI·스크립트:**
  - CI가 매번 gekkio.fi에서 mooneye 압축 파일을 캐시 없이 내려받는다. 그 서버가 내려가면 CI가 실패한다.
  - `fetch-test-roms.sh`에서 curl이 실패하면 `*.tmp` 파일이 남는다. 다음 실행에서 덮어쓴다.
  - 같은 스크립트의 mooneye 완료 표시는 압축 파일 해시만 보고, 풀어 둔 파일이 아직 있는지는 보지 않는다.
- **문서·잔여 코드:**
  - `step()`·`run_frame` 문서 주석이 한 step의 범위를 실제보다 작게 설명한다.
  - `Bus::cycles()`는 테스트 말고는 부르는 곳이 없다.
- **성능:**
  - 줄마다 스프라이트 `Vec`을, 프레임마다 RGBA `Vec`을 새로 할당한다.

## 3. 스펙에서 일부러 뺀 기능 (스펙 §1.5)

원하면 새 마일스톤으로 설계부터 다시 시작한다(brainstorm → spec → plan).

- **코드 서명:** 스펙에 "초기에는 미서명, 이후 검토"라고 되어 있다. 지금은 Windows SmartScreen과 macOS Gatekeeper 경고가 뜬다.
- **적외선 통신·인터넷 링크:** 링크 케이블은 같은 네트워크(TCP)만 지원한다. 크리스탈 모바일 어댑터, 적외선, 인터넷 너머 연결은 없다.
- **사이클 단위 정확도:**
  - 지금 PPU는 스캔라인 렌더러다.
  - 픽셀 FIFO로 바꿀 수 있게 렌더러를 별도 함수로 분리해 두었다(스펙 §4.4).
- **게임보이 어드밴스:** 범위 밖. 별도 프로젝트 규모다.

## 4. 다른 컴퓨터에서 이어서 작업할 때

- **릴리스 서명 비밀 키:**
  - 저장소에 없고, 저장소에 넣으면 안 된다.
  - 릴리스는 GitHub Actions 시크릿으로 서명하므로, 로컬에 키가 없어도 태그 푸시로 릴리스할 수 있다.
  - `cargo xtask gen-key`는 `--rotate` 없이는 `release/policy.pub`을 덮어쓰지 않는다.
- **릴리스 순서:**
  1. `release/vX.Y.Z` 브랜치를 만든다.
  2. `Cargo.toml`의 `[workspace.package] version`과 `release/policy.toml`의 `message`를 바꾼다. `minimum_supported`는 치명적 결함이 있을 때만 올린다.
  3. PR을 만들고 CI가 통과하면 병합한다.
  4. `cargo xtask check-tag vX.Y.Z`로 버전과 태그가 맞는지 확인한다.
  5. `git tag -a vX.Y.Z`로 태그를 달고 푸시한다.
- **테스트 ROM:**
  - 저장소에 없다. `scripts/fetch-test-roms.sh`로 내려받는다.
  - `ARAGORN_REQUIRE_TEST_ROMS=1`로 테스트를 돌리면 ROM이 없을 때 실패한다.
- **리눅스 빌드:**
  - `libudev-dev`(gilrs)와 ALSA 개발 패키지가 필요하다.
  - linuxbrew의 pkg-config를 쓴다면 `PKG_CONFIG_PATH=/usr/lib/x86_64-linux-gnu/pkgconfig`를 설정한다.
